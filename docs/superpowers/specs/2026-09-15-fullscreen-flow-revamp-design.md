# Full-screen flow revamp

**Date:** 2026-09-15
**Status:** approved, in build

## The ask

Every step of the ballot becomes one whole screen. No page scrolling anywhere. Step one
is "Who are you?" — a themed input whose results appear as you type, replacing the A–Z
list of 73 names. Identity is the landing: opening the link puts you on that question.

## Decisions

Both settled with Wayne before the build:

- **Never scroll.** A hard `100dvh` per step. Where options do not fit — venue photos on a
  phone — they become a horizontal swipe deck, one card per viewport, rather than a column
  that runs past the fold.
- **Identity is the landing.** `/` opens on "Who are you?". The cover photo and the
  editorial header are retired; the intro stays reachable at `/?intro`.

## Structure

One route. `/` is a server component that reads the roster and who has already voted, then
hands off to a single client `<Flow>` owning all seven screens. No navigation between
steps, so there is no latency and no route seam mid-flow. `/vote?name=X` survives as a
redirect so links already shared in the group chat still open the flow.

Back is wired to step-back by pushing a **hash** — `#where`, `#food` — with a `null`
history state. Both details are load-bearing and were found the hard way: Next owns the
history state object, so writing our own clobbers the router's and turns the next Back
into a full page reload; and keeping the step in the hash rather than in a query
parameter leaves the pathname and `searchParams` untouched, so traversal never reaches
the server component. A hash present on first load is stripped, because a shared
`#wear` must not drop someone into a ballot they have not started.

Rejected: keeping the `/` → `/vote` split (reintroduces a page load between step 1 and
step 2, which is the seam the revamp exists to remove) and a route per step (a server
round-trip per question, and draft state still has to live client-side regardless).

### The seven screens

| # | Step | Asks | Options |
|---|------|------|---------|
| 01 | Who | identity | typeahead over 73 names |
| 02 | When | `dateId` | 3 |
| 03 | Where | `venueId` | 2 (per track) |
| 04 | Food | `foodId` | 3 |
| 05 | Wear | `paletteId` | 4 |
| 06 | Day | — | display only |
| 07 | RSVP | `attending` | 3 + summary |

Step 06 keeps its place but sheds the ten-moment timeline, which would not fit a viewport.
In-flow it becomes an at-a-glance card — runs, moments, games, one pulled line. The full
timeline moves to `/done`, where there is room to scroll.

### Shell

Every screen is the same three-row grid, `h-[100dvh]`, `overflow-hidden`:

- **auto** — back chevron, step index (`01 · WHO`), progress dots, name chip once known
- **1fr** — `min-h-0`; the question and its content. The only row that flexes.
- **auto** — error, primary button, `env(safe-area-inset-bottom)` padding

Dots indicate; they are not a stepper. Answered steps are tappable, later ones inert. The
sticky header, fixed footer bar, `Stepper` and running plan rail are all removed. The plan
summary survives only on the RSVP screen, as the receipt you check before submitting.

### Deck

Below `md`, options are a CSS scroll-snap track (`snap-x mandatory`, `overscroll-contain`)
— one card per viewport, dots underneath, arrow keys on desktop. No library. At `md` and
up the same component renders a grid, because 2–4 cards fit a wide screen and swiping a
roomy layout would be worse, not sleeker.

Children are `w-full shrink-0 snap-center` with no gap on the mobile track, so
`scrollLeft / clientWidth` rounds to the active index exactly.

The deck takes a `fill` prop. On by default and not cosmetic: a card whose media is
`flex-1` — a venue photo, a palette's swatch field — collapses to zero height in a
content-sized grid row, because its `h-full` has nothing definite to resolve against.
Dates and caterers are built from natural-height content, so they set `fill={false}` and
centre instead of stretching. The same chain has to hold all the way up: the wrapper
inside `Screen` grows, or everything below it is content-height and the media collapses.

### Identity

At rest the input sits alone above a count. Typing reveals up to six ranked matches —
prefix before word-start before substring, ties alphabetical. `↑` `↓` to move, `Enter` to
pick. Already-voted names carry a quiet tag but stay selectable, because re-voting
overwrites the member's row in place, which is what `submitBallot` already does.

The results list lives in the `1fr` row so that when the mobile keyboard opens and `dvh`
shrinks, the list compresses rather than pushing the button off-screen.

Search is a pure function in `lib/roster-search.ts` — `lib/roster.ts` is generated by
`pnpm seed` and must not grow hand-written code.

## What does not change

`lib/schema.ts`, `app/actions.ts`, `lib/sheets.ts`, `/results/[secret]`, and the intro are
untouched. The province/city invariant, its tests, and the `Votes!A:H` column contract all
hold exactly as they are. This is a surface rebuild, not a data change.

## Testing

`lib/schema.test.ts` passes unedited — that is the proof the data contract did not move.
New unit tests cover the typeahead's ranking and accent folding. Deck behaviour is CSS and
is checked in a browser, not a test.

Verified in Chrome at 402x844 and 360x640: every one of the seven screens reports a
document height exactly equal to the viewport, with no scrolling on either axis. Back and
Forward step through the flow without a reload, and a partial saved draft resumes at its
first unanswered question.

Submitting a ballot writes to the live workbook; clear it with
`pnpm clear-vote "Surname, Firstname"`.
